## VRCAM handoff

The first TPP candidate read the director's selection again during RTT creation.
A short unavailable selection (including its100ms freshness guard) could choose
the ordinary FPP component for VRCAM even while MAIN was stable. This is a
possible source of the reported jump; the short pre-change capture did not
reproduce the rare frame, so it is not a measured exclusive diagnosis.

Current source removes this separate selector. Generic MAIN writes carry an
external-view bit through exact pose ancestry; blending ORs that ownership
across active inputs. Completed director output and the actual selected MAIN
read publish a value snapshot with its exact head label and FOV. Publication
requests the same native vtable+240 refresh used by LocateCamera's device/BD
push. VRCAM's native descriptor takes that complete MAIN pose and changes only
signed IPD. No new XR sample is acquired for that eye.

Missing MAIN observations retain this value; only explicit FPP/device ownership
or changed player/eye/origin invalidates it. No expired pointer is read. Steering
requires a recent snapshot; retaining an old render viewpoint cannot keep issuing
an old steering command indefinitely. Live ordering/latency verification is still
required for this candidate.
