Отчёт пользователя:

Переключение выполнялось обычной кнопкой/колёсиком.

## Что установлено по дампу

Исключение записи0xC0000005: `Cyberpunk2077.exe+0x144A1A`, поток23980.
Инструкция `and [rcx+8],rdx` находится в выделении/разделении блока памяти.
При запросе0x848 байт размер выбранного свободного блока оказался нулевым;
вычитание размера запроса породило0xFFFFF7A0 и обращение почти на4ГБ дальше.
Это повреждение метаданных heap до данного выделения.

Помимо первоначального stack scan, восстановлена цепочка по PE UNWIND_INFO:
`144A1A → 1448C9 → 141EF3 → BF4A3F → BF49F8 → 14BAA2 → 2790CA → B53F88 → 1D51ED`.
Дальше находится worker job обновления привязок компонентов.
Объект принадлежит игроку и имеет vtable морфируемого skinned-mesh компонента.
Ни Lua/CET, ни новая проверка melee не находятся в этой цепочке.
Сам дамп не показывает инструкцию, которая ранее испортила заголовок блока:
он не доказывает конкретного автора повреждения или независимость от Lua.

## Найденный дефект перепривязки VRIK

На живом PID23520 через штатные equipment requests проверены Gorilla Arms,
пистолет, дробовик и катана. ReadProcessMemory использовался только для чтения.
При Gorilla Arms размер meta-rig меняется620↔768. Старый pose-буфер освобождается,
а счётчик VRIK останавливается до перепривязки примерно на0,2–0,3с.

`VRIK_DoArmPlayer` публиковал новые track pointers перед обновлением индексов,
числа костей, FK prefix, reference pose и solve cache. В записях наблюдаются
промежуточные сочетания нового адреса и старых размеров, в том числе
boneCount620/FKCount768. Обработчик поз не синхронизировался с перепривязкой и
не проверял вместимость текущего poseDesc. Это реальное небезопасное окно при
смене скелета; связь с конкретной более ранней записью из дампа остаётся выводом,
а не доказанной точкой падения.

Исправление:

- Общий SRW lock защищает перепривязку и обработку поз игрока вместе с FK/cache.
- Новые адреса публикуются после полного обновления метаданных. Неудачная
  перепривязка оставляет обработку игрока отключённой.
- После получения lock обработчик повторно проверяет принадлежность буфера и
  его реальную вместимость перед любой записью в кости.
- SEH finally освобождает lock при раннем выходе и исключении. Проходы NPC
  не берут этот lock. Переключение head-aim cache также находится под защитой.

## Проверки

Release DLL собрана. Все47 тестов VRIK проходят. Новый `pose_buffer_rebind`
использует настоящий производственный FK и pose-буфер перед PAGE_NOACCESS:
старые768 индексов на меньшем буфере воспроизводят выход за границу, проверка
размера отклоняет этот вызов, корректная перепривязка восстанавливает обработку.
Второй поток проверяет ожидание завершения перепривязки.
Тестовый стенд обновлён для существующих границ BodyYawFollowOffset и debug gate.

До установки исправления несколько штатных переключений прошли без краша;
это подтверждает непостоянный характер проблемы, но не исправление.

отчёт установки: `build/roomscale-plugin-deploy-20260924-012530/deployment.json`.
