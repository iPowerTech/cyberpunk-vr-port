# CAS Sharpening

The General overlay has a `CAS Sharpening` slider, `0.000..1.000`, persisted in the existing
`xr_sharpmix` setting. Its default is `1.000` in both the settings structs and INI; `0` bypasses the pass.
The existing `xr_sharpness` key is CAS Emphasis, default `0`, not an on/off switch.

## Local reverse evidence

Inspected `C:/Users/dariulone/Desktop/RealVR_reverse_project/input/RealVR64.dll`
through its IDA database. Addresses below are RVAs (image base `0x180000000`).

- `draw_realvr_overlay_main_panel`, `0x31944D..0x3194F7`: Emphasis binds runtime
  `+0x841AF4` (`FilterSharpness`); Deblur binds `+0x841AF8` (`FilterSharpmix`).
  Both sliders use minimum 0, maximum 1 and format `%.3f`.
- `0x31950F..0x319541`: Deblur is multiplied by the float at `0x66B3A0` (4.0)
  before reaching the renderer. Emphasis is passed unchanged.
- `runtime_rvr_ctor`, `0x316183..0x31618A`: Emphasis defaults to 0 and Deblur to 1.
- The D3D11 shader creation call at `0x2CDA38..0x2CDA48` identifies `g_BlitPSCAS`
  at `0x5D20A0`, size `0xA28`. D3DDisassemble confirms a point-sampled 3x3 CAS
  neighborhood, peak `-1/(8-3*Emphasis)`, saturated CAS output, then
  `saturate(center + 4*Deblur*(CAS-center))`.

This is CAS with an extended blend amount, not an ordinary 0..1 CAS-strength
slider. [AMD's CAS documentation](https://gpuopen.com/manuals/fidelityfx_sdk/samples/contrast-adaptive-sharpening/)
describes the underlying sharpness parameter; RealVR's UI additionally scales the blend.
The implementation uses the port's existing CAS shader, not embedded RealVR bytecode.

## Integration

The submit path selects MAIN, VRCAM, or framegen color first, then applies the
same pass to each eye. Original capture textures and framegen history remain in
COPY_SOURCE. One private texture, serialized on the submit queue, receives a
copy and has a permanent SRV. Per-draw root constants avoid upload-buffer reuse.
CommandResources retains textures, descriptor heaps, root signature and PSO
through GPU completion, including initialization changes and shutdown.

Typed UNORM views handle runtime typeless images. For typed sRGB targets, the
shader decodes its result before the RTV re-encodes it, preserving the encoded
color domain and avoiding a gamma shift. Unsupported formats fall back to the
original copy; the pass does not clamp floating-point HDR images to SDR.
