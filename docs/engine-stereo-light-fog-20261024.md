# Facade light flicker and bridge fog, game 2.5

The distant-light fix is installed and enabled. The separate fog issue is
reproduced but **not fixed** by this change. DLSS Transformer and the user's
Medium fog setting are preserved.

## Distant lights: confirmed cause and correction

In `lightjumping.rdc`, the upper faint halo and the middle bright halo are lit by
one source at (-2358.86, -981.86, 20.93828); the lower halo uses another at
(-2358.86, -981.30, 16.22220). Both have radius 5 and zero authored flicker
amplitude. Their contribution is generated by the distant-light raster draw
62695, before fog and DLSS.

The native culler (`6a1544708bf0067e`, event 61974) projects light bounds using
MAIN's union projection, then queries a depth pyramid containing two separate
eye images. For the upper/middle source it queries X=100.68..116.56, while the
actual eye rectangles are approximately X=62.90..72.82 and X=135.57..145.48.
Geometry at unrelated positions can therefore make these lamps disappear,
including while the head is stationary.

`tools/asym_tests/stereo_distant_light_shaders.py` builds the replacement:

- Use each eye's world-to-clip matrix from existing b12 rows 93 and 113.
- Project the light AABB into that eye's HiZ rectangle, including native padding.
- Add a one-base-texel conservative margin and retain eye-plane crossings.
- Keep a light when either eye sees it. Frustum, distance/LOD, intensity and
  authored animation logic remain native.
- Branch around the new reads in mono and retain the exact native result.

RenderDoc verified the b12 block is bound at the culling dispatch; both matrices
match the subsequent light-volume raster matrices byte for byte. This is not a
hardcoded headset projection or a blanket occlusion disable.

Runtime group 13 uses `stereo_distant_light/6a1544708bf0067e.dxil` and defaults
`CyberpunkVR_StereoDistantLightPatch` to 1. Packaging and deployment scripts
include the new file. PSO ownership/lifetime machinery is unchanged.

## Validation

Two authorized game launches were serialized with capture replay. The first
isolated the cause using a stereo-only occlusion bypass. The second tested the
actual eye-local replacement with native/fixed/native/fixed recordings at an
identical camera position and orientation.

Maximum change between adjacent screenshot samples, luminance on a 0..255 scale:

| Halo | Native A | Fixed A | Native B | Fixed B |
| --- | ---: | ---: | ---: | ---: |
| Upper | 3.559 | 0.179 | 3.838 | 0.134 |
| Middle | 30.308 | 0.209 | 32.023 | 0.208 |
| Lower | 14.055 | 0.166 | 14.206 | 0.213 |

Each recording contains 150 samples over 12 seconds; all window reads were valid.
Camera position and quaternion were constant. Nearby control surfaces had no
comparable jumps. The replacement pipeline built successfully, with no failure.

The final shader adds an explicit mono branch around the eye-specific reads.
Replay comparison of sorted 24-byte light records verifies:

- Native result: 459 lights.
- Final stereo result: 547 lights, identical records to the live-tested candidate.
- Forced mono branch: 459 lights, byte-identical records to native.

Release build and packaging-script syntax checks pass. The final enabled-by-default
DLL was installed after closing the game; it was not launched a third time.
These tests cover the supplied scene and capture, not a complete game regression.

Evidence is in `scratch/light-fog-jumping-20261024/live2/` and
`light/verification.json` under the same scratch folder.

## Fog: reproduced, unresolved

The user confirmed the orange haze above the Mac N' Cheezus bridge also jumps at
rest. Broad ROI means obscure the changes, which concentrate along the lit bands.
Disabling `RenderFogOverlay` removes the haze and most of those changes.

For the stationary 450x240 bridge crop, after a one-pixel Gaussian filter, the
99th percentile of each pixel's maximum adjacent-sample luminance change was:

| Probe | Value |
| --- | ---: |
| Native Medium fog | 11 |
| Adaptive-history reconstruction candidate | 13 |
| Ultra fog | 3 |
| Fog overlay omitted | 2 |

Further candidates were tested and were **not promoted**:

- A stereo fog tile-closing plane spans one horizontal unit although the group
  advances by two. Widening it changes almost none of the supplied bridge ROI.
- Fog composite UVs omit a small raster-jitter correction. A candidate cancels
  the measured projection/volume UV discrepancy to below 5e-9, but live A/B/A/B
  still gives a luminance-step percentile of 11 in all four recordings.
- Switching temporarily from Transformer to Legacy at the same input resolution
  also gives 11 after excluding the model-switch settling period. Transformer
  was restored.

The captured scattering history is valid and contributes at weight 0.98 at
sampled contributing froxels. A blanket claim that Engine Stereo loses all fog
history is not supported. Higher volume resolution helps, but this alone does
not identify the full cause or establish a correction for Medium.

Both diagnostic fog shader groups were removed from the production DLL; test
files were archived outside the game. Game settings were compared semantically
with their backup and match. Simulator settings were restored exactly. The game
and all RenderDoc replay sessions are closed.
