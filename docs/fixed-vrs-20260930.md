# Fixed Peripheral VRS

## Scope

Optional D3D12 Tier 2 variable-rate shading for native `RenderElements` opaque
material draws in both eyes. Default is OFF. It is independent of the existing
foveated-DLSS implementation and does not change game resolution, DLSS settings,
frame generation, async compute, geometry LoD or shadow/culling policies.

Settings: `xr_vrs` (0=off, 1=2x2, 2=4x4), `xr_vrs_width`, `xr_vrs_height`,
`xr_vrs_offset_x`, `xr_vrs_offset_y`. Default center is 70% x 65%, centered.
The overlay exposes these under VARIABLE RATE SHADING. Changes debounce for one
second; turning off is immediate. Requested 4x4 falls back to 2x2 if unsupported.

The center rectangle and every intersecting hardware tile remain 1x1. Mode 4x4
has a 2x2 transition extending 8% of image width/height beyond that rectangle.
Each eye uses its actual render viewport, not desktop/output dimensions.

Per the [Microsoft VRS specification](https://microsoft.github.io/DirectX-Specs/d3d/VariableRateShading.html),
VRS does not automatically accelerate compute shaders or DLSS; depth/stencil
export forces fine shading. It can change peripheral interpolation, derivatives
and mip selection. This is a quality/performance option, not a lossless rewrite,
and no universal 15-30% FPS gain is promised.

## Implementation Boundaries

- Only recognized opaque 3/4-MRT, single-sample graphics pipelines with depth;
  no blended, tessellated, geometry/mesh or view-instanced pipelines.
- No shadow-only targets, HUD, other graph nodes, shifted/multiple viewports,
  or unknown command-list state. Unsupported hardware is pass-through.
- Native rate, both combiners and image are restored before incompatible draws,
  native VRS changes, bundles and command-list Close. Reset/ClearState invalidate
  recording bindings. Unknown bundle state stays on native fallback.
- Repeated compatible draws reuse the binding. Per-recording state is cached
  without a global per-draw lock; D3D12 requires serialized recording per list.
- Rate images are immutable R8_UINT textures. Upload is asynchronous on the game
  queue; a map is selectable only after its initialization fence completes.
  Existing CommandResources retains images through recording/replay/GPU completion.
  Cache eviction and setting changes cannot release an in-flight image.
- Quick disable/re-enable requires a fresh known recording. No native state
  from an unobserved disabled interval is reused.

## Verification

Build `tools/vrs_tests` with CMake/Visual Studio x64 and run CTest Release.
CPU tests cover hardware tile sizes, partial edge tiles, center protection,
offsets, normalization, unsupported 4x4 fallback, INI keys and opaque PSO gates.

Hardware tests on RTX 5070 Ti, with D3D12 debug validation:

- Identical MAIN/VRCAM results; fine center byte-exact against native rendering.
- 256x192 fixture: 49,152 native PS invocations vs 30,720 with 2x2 (37.5% fewer).
  This is fixture shader work, NOT Cyberpunk FPS.
- Native image/rate/nondefault combiners restore exactly; HUD/unsupported nodes
  and Off produce the native image. Repeated compatible draws emit no redundant
  VRS binds. 4x4 and settings rebuild also pass.
- Shared pipeline-stream parser regression test passes.

## Live Measurement Log

All runs use framegen OFF, native DLSS Balanced, async compute ON, the same save
and stationary simulator pose. Readiness requires native second-eye GPU capture
plus a nonblack stereo image, not only QuickBoot's scripting status.

PID 13136: Off 78.50 / 78.35 / 76.69 FPS; 2x2 57.86 / 52.93 FPS; 4x4 59.45 FPS.
GPU utilization fell from 96% to 78-80%. That implementation is REJECTED and was
replaced with persistent compatible-group bindings and cached recording state.
Evidence: `build/gpu-audit-20260930/fixed-vrs-live/`.

PID 18428 crashed before VRS activation at game RVA 0x1DB1EC (read 0x70058).
Its stack-scan address sequence matches the pre-VRS PID 4232 crash from 10:41.
This is evidence of a preexisting crash signature, not a proven root cause.
CrashReporter was closed. Matching DLL/PDB: `build/fixed-vrs-crash-18428/`.

The game already uses an adaptive shading-rate image. Earlier verified native
image readbacks in `docs/single-pass-stereo-20260927.md` contained approximately
5305 fine and 3338 2x2 tiles (about 39% coarse). This mode replaces that policy
with a fixed fine center; it does not enable previously absent hardware VRS.

## Other Proposed Directions

- Per-eye frustum culling already runs natively. `CyberpunkVR_CullReuseMode=0`
  leaves both `DoCulling` calls intact; no new culling optimization is claimed.
- Shared cascades require common raster/sampling transforms, correct atlas
  ownership, both-eye coverage and scheduling. A small IPD does not prove that
  deleting one view's cascade draws is correct. Existing skip controls remain off.
- Geometry LoD is a separate quality option, not enabled as part of VRS.
- Existing single-pass depth tests cover one material group and save only
  0.056-0.059 ms there. They do not establish a full-renderer FPS gain; the
  diagnostic scheduling wait must not be put into a production per-frame path.
