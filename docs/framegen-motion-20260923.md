# Framegen: проверка поворотов головы и позиционного джиттера

Проверена установленная DLL `1fb57a90…` в PID21064, OpenXR Simulator90Hz,
2560×2560 на глаз, игровые depth/MV1485×1485. Оба генератора независимы:
NVIDIA OFA + собственный интерполятор и полный конвейер FidelityFX.

Для каждого режима выполнен25-секундный прогон: покой, плавные повороты,
быстрые повороты и возврат. Получились yaw до42,14°, pitch13,05°, roll4,69°.
Позиционные колебания: до2мм по X,1мм по Y,1,5мм по Z; максимальное суммарное
отклонение2,54мм. Команды поступали через штатный `head_pose_command.json`,
без клавиатуры, смены фокуса и записи памяти игры. Исходная поза восстановлена
в `finally`; ошибка возврата позиции CCT0мм в обоих прогонах.

Готовые записи проверены на наличие обеих текстур, одинаковые ожидаемые и
исполненные маски7, успешную оценку апскейлера, размеры и соответствующий view.
Проверены сквозные ID при захвате и публикации. Не было нулевых ID захваченных
картинок или смешанных пар «один submit ID нулевой, второй ненулевой».
У синтетического кадра оба submit ID намеренно0: его поза интерполирована и
не является квитанцией одного реального изображения.

Счётчики изменения источника копирования и входа VRIK, пропусков захвата по
ресурсам/слотам/fence/reset и отсутствия второго глаза не выросли. Диагностический
счётчик EyePaired выключен обычным режимом логирования; его0 не использован как
доказательство отсутствия/наличия пар. Пары проверены непосредственно по
стабильным снимкам камер одного native render frame. Это чтения работающего
процесса, поэтому соседние счётчики могут расходиться на кадр на границе замера.

## Частота и затраты в этом запуске

В покое оба режима давали примерно45 реальных и45 сгенерированных кадров.
На движении медиана OUT: NVIDIA89,57/89,15, FidelityFX87,96/87,51 FPS для
плавного/быстрого сценария. Минимумы: NVIDIA88,01/87,24, FidelityFX85,06/85,09.
Это не потеря привязки MV/depth; в эти интервалы были задержки/повторы и иногда
повторное заполнение истории. Постоянные90 уникальных кадров не заявляются.

Отслеживаемая VRAM: NVIDIA до279MiB, FidelityFX456MiB. Медиана GEN при движении:
NVIDIA7,1–7,7мс, FidelityFX2,4–2,6мс. GEN измеряет интервал в очереди от начала
подготовки до готовности результата; он включает ожидания и возможную работу
игры между списками. Это не изолированная занятость вычислительных блоков GPU.
CPU ms на панели — интервал реальных кадров, включая ограничитель, не CPU busy.

В ходе анализа обнаружена ошибка краткого FPS-окна: редкие повторы оценивались
по интервалу между собой, поэтому два повтора могли кратко выглядеть как20 FPS;
обычные частоты немного занижались из-за фазы опроса. Исправлен расчёт по полному
окну наблюдения с поддержкой высоких FPS, когда кольцо заполняется быстрее2с.
Регрессии sparse repeats и high-rate ring, а также history/pacing проходят.
В отчёт добавлены накопительные real_submitted/repeated для точных дельт.

## Данные и границы проверки

`tools/framegen_tests/motion_probe.py` воспроизводит сценарии. Сводка:
`build/framegen-native/motion-summary-21064.json`; полные данные:
`motion-21064-nvidia.json` и `motion-21064-fidelityfx.json` в той же папке.
Снимки готовых записей включают повторные наблюдения одних GPU-ресурсов,
а не5910/6001 уникальных кадров. Данные игровых текстур не считывались обратно:
проверены их захват, метаданные, время жизни и привязки, не каждый пиксель MV.

Прогон подтверждает целостность данных при движении в симуляторе. Субъективная
плавность, артефакты на сложных объектах и комфорт в физическом шлеме требуют
отдельной проверки. Пользователь вернулся: автоматически запускать игру больше
нельзя. Коммит для этой функции не запрошен.
