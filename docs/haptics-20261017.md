# Controller haptics (2026-10-17)

## How the game does it, and why the port does not route that

Cyberpunk's own rumble is Wwise motion: events such as `rumble.local.light_pulse` are rendered by
AkMotion sinks for XInput (`XInputSetState`, looked up through `GetProcAddress` in sub_141BE9D40 /
sub_141BE9ED0), DirectInput and ScePad (DualSense).

That signal is two pad motors with no hand, so it cannot say "left hand on the belt" or "both hands on
the rifle". The port drives the controllers itself instead, from the events it already knows.

## Channel

`OpenXRManager` creates the vibration output action `haptic`, per hand. It is bound to
`/user/hand/{left,right}/output/haptic` inside each profile's single suggest call, because a second
call would replace the profile's input bindings. All five profiles take it (Touch, Index, Vive, WMR,
simple; Touch goes from 17 to 19 bindings). The Steam Frame profile does not get one: its output paths
are unknown, and one unsupported path rejects the whole profile.

`src/Runtimes/Haptics.cpp` handles the events:

- Callers queue them from any thread. The XR frame thread plays them right after `xrSyncActions`.
- Each event is an envelope of up to three segments (amplitude, ms).
- There is one envelope per hand. A new event replaces the current one unless the current one has a
  higher priority and is still running.
- The frequency is `XR_FREQUENCY_UNSPECIFIED`. Controllers answer frequency very differently, so the
  profiles differ in strength, length and decay instead.

| Profile row | Event | Envelope (amp/ms) |
| --- | --- | --- |
| 0 handgun | round (class 1) | 0.85/28, 0.25/30 |
| 1 rifle, SMG, LMG | round (class 2) | 0.60/22 |
| 2 shotgun | round (class 3) | 1.0/55, 0.55/70, 0.2/60 |
| 3 sniper, precision | round (class 4) | 1.0/45, 0.6/60, 0.25/90 |
| 4 belt | a hand reaches a belt element | 0.30/14 |
| 5 melee block | melee hit taken on the block | 0.9/40, 0.4/50 |
| 6 melee parry | melee hit parried | 1.0/20, gap 35, 0.75/25 |
| 7 bullet block | bullet stopped by the blade | 0.65/30, 0.2/30 |
| 8 bullet deflect | bullet deflected or parried | 1.0/15, 0.45/25 |
| 9 grenade pin | the hand that pulled the pin | 1.0/18, 0.35/30 |
| 10 grenade pin | the hand holding the grenade | 0.45/25 |

## Hands

Rounds go to the right hand, plus the left when `CyberpunkVR_TwoHandActive` is set: in a 2H grip both
hands feel the round, held in one hand only one does (`CyberpunkVR_HapticSupportMul` = 1).

Blocks and deflects follow the same rule. The plugin adds the left hand when the weapon is in a 2H
grip. Fists, gorilla arms and mantis blades always use both hands, because they guard with both arms.

## Sources

- **Rounds**: `RecoilOnShot` (`src/Anim/Recoil.cpp`) calls `cvr::haptics::Shot`. This is the place that
  already turns provider calls into one round, so there is one envelope per round, and full-auto
  stacks round by round.
- **Block, parry, bullet block, bullet deflect**: `mods/redscript/CyberpunkVRPort_Haptics/vrport_haptics.reds`
  wraps `DamageSystem.ModifyHitData`. After `DamageManager.ProcessDefensiveState` has run, it reads the
  hit's flags for the player: WasBulletDeflected/Parried -> 13, WasBulletBlocked -> 12,
  WasDeflected -> 11, WasBlocked -> 10. The projection pipeline (damage preview) is skipped. The
  script calls `VRHapticEvent(kind, hands)`.
- **Belt**: `CyberpunkVRPort_TacticalBelt/init.lua` `updateHighlight`. This fires on the edge, when an
  element lights for a hand, so a hand resting on a pouch does not keep buzzing.
- **Grenade pin**: `grenade/grenade.lua` at "pin pulled". Kind 2 goes to the free hand, kind 3 to the
  holding hand.

## Settings and stats

- **ini**: `xr_haptics=1` turns it all on or off. `xr_haptic_scale=1.000` scales every profile and is
  clamped to [0, 2].
- **Live exports**: `CyberpunkVR_Haptics`, `CyberpunkVR_HapticScale`, `CyberpunkVR_HapticSupportMul`,
  and `CyberpunkVR_HapticProfiles[11][6]` (three amp/ms pairs per row).
- **`CyberpunkVR_HapticStats[8]`**:
  - [0] events accepted
  - [1] segments applied, left
  - [2] segments applied, right
  - [3] last xrApplyHapticFeedback result
  - [4] last profile row
  - [5] dropped
  - [6] rounds
  - [7] script events

- Lexington, one-hand grip, four rounds (magazine 20 -> 16): four handgun envelopes, eight right-hand
  segments, none in the left.
- `VRHapticEvent` from CET for the belt (left), a bullet deflect (right), and the pin (left) with its
  holding hand (right): three segments per hand. Every apply returned XR_SUCCESS.
- The redscript compiles.
