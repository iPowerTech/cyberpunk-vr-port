# HUD free-look panel

This records the initial panel implementation. Current appearance, stereo and
per-element settings are described in `hud-style-layout-20260923.md`; all panel
controls now live in the dedicated HUD tab.

Ordinary HUD follows the same yaw cone as the menu: hold inside the cone, catch up
at 3 rad/s, stop within 2 degrees and restore the free zone. Translation follows the
current OpenXR head position. The quad uses the current predicted display pose,
independently of the pose associated with the game image. It is submitted for both eyes.

Defaults: enabled, 60-degree cone, 65.4-degree vertical FOV, 1.5 m distance.
Controls are in General / View / Resolution and persist as `xr_hud_*` keys.

## Source separation

Read-only live examination of PID26036 found 70 `inkHUDLayer` entries, 27 active
separate-window entries. Ordinary health, minimap, quest tracker and hotkeys have
their own DynamicTexture and slot image. Crosshair/world markers/projected scanner
widgets use the direct HUD path. The panel collects only separate-window slots.
The existing world-marker composition into MAIN and VRCAM remains in place.

Layout comes from each immediate parent's native GetChildPosition/GetChildSize,
summed up to the layer window. Source textures are cropped to their widget content;
they are not full-screen images. Live health: 2000x166 texture, position (53,130) in
a 2560x2560 HUD window. Source-window/controller visibility is never changed.
Only the final slot image draw is hidden after the XR consumer successfully prepares
the replacement. The game-requested visibility and original layout flags are restored
on disable, menu, source failure, consumer timeout or layer replacement.
The tint-based first revision was rejected in live testing because its old HUD shadow
remained visible. Ordinary SetOpacity(0) also proved unsuitable: its layout became 0x0.

`new_phone` and `songbird_holocall` are authored as direct HUD roots. The native entries
copy is intercepted before spawning to enable separate windows for exactly these names.
World/projected entries retain their original settings.

Runtime signatures guard the layout, visibility, entries-copy and release helpers. Source acquisition also
checks backing vtable, dimensions, texture format and native read state. Native
handle leases keep the engine's backing heap alive, in addition to COM references.

The draw mask preserves `affectsLayoutWhenHidden` and avoids the ImageWidget hiding
callback: that callback unloads the image even when the layout flag is preserved.
The SetVisible interception records the game's desired state separately, so later UI
jobs cannot accidentally re-enable drawing of an extracted slot. Targets are published
as an immutable shared snapshot that owns widget handles through concurrent callbacks.

## GPU lifetime

Present composes into three independent transparent canvases on the game's existing
queue. Each producer slot has its own allocator, descriptor ring and source leases.
It cannot be reused while its producer fence is pending or a reader holds the frame.
The XR consumer holds its frame through its copy fence. Source textures remain in
the native shader-read state; the panel never changes the game's resource tracker.
Swapchain images enter and leave the copy in RENDER_TARGET as required by the existing
D3D12 XR path. XR_TIMEOUT_EXPIRED preserves the acquired image for the next wait.
Capture identity is a serial number, not the coarse GetTickCount64 timestamp.

## Cold-start correction, 2026-09-23

PID23536 at 10:59 exposed a bootstrap defect in the saved Lua module: its top-level
`CName.new("inkHudEntryInfo")` ran before CET installed game type bindings. The log
reported CName=nil during require, then HudPanel=nil in init.lua; GetMod(Stereo)
returned nil. The native DLL and HUD hooks loaded normally, but no Lua publication
reached the panel. The previous live patch/fixture had started with game APIs already
available and therefore did not validate this startup path.

CName construction is now deferred until the first HUD update after initialization.
VRCAM hotkey registration also moved to module load, where CET provides its binding
registration API, instead of calling an unavailable registerHotkey inside onInit.
The complete production bootstrap passes two synthetic cold starts, and mutations
restoring either original defect are rejected. Existing phone-bound tests also pass
with game types deliberately absent during module loading.
