# Settings, launcher, and unsupported shading-rate images

Changes for [#70](https://github.com/dariulone/cyberpunk-vr-port/issues/70),
[#71](https://github.com/dariulone/cyberpunk-vr-port/issues/71), and
[#93](https://github.com/dariulone/cyberpunk-vr-port/issues/93), 28 September 2026.

## UserSettings (#70)

The cascade guard was already removed and stays removed. `first_launch=0`
returns without inspecting or modifying the player's game settings.

For `first_launch=1`, parse both settings files using the existing OpenXR
JsonCpp dependency, then match `group_name` and option `name`. Copy preset
values and selection indices, retaining the player's schema, root metadata,
and unknown groups/options. Insert missing nonpersonal preset entries.

The user-approved exclusions are `/language`, `/audio`,
`/gameplay/difficulty`, `/gallery`, and `/gameplay/misc` options
`EnableTelemetry` and `EnableCloudSaves`. Those preferences remain untouched.
All other shipped settings, including graphics, input, HUD, and comfort,
are applied once. The shipped preset currently has 307 such options.

Invalid JSON, duplicate groups/options, incompatible types, and unreadable
files fail without replacing the original. Changed settings are flushed to
a unique temporary sibling; the original is backed up before atomic rename.
An identical preset causes no file rewrite or redundant backup. The first
launch flag is cleared only after a successful merge/install.

## Launcher (#71)

Publish the game's HWND and install OS input hooks before showing the launcher.
While it is open, release clipping/capture, reject game cursor recentering,
and bypass virtual coordinate/window-size scaling. The native window is topmost,
foregrounded, and centered on the game's monitor. Temporarily hide a visible
game window, preserving its dimensions; restore it on exit or failure.

Use `DefWindowProcW` for the Unicode class/title. Closing the launcher no longer
posts an application-wide `WM_QUIT`. An external quit request is preserved.
Reentrant launcher calls are ignored and resources/state are cleaned up.

The actual dialog and OS input handlers are exercised on a separate, unshown
Windows desktop. Tests cover title, stacking, hidden fullscreen owner, input
passthrough, saving, close, external quit, reentry, and failed creation. QuickBoot
startup message pumping also passes. Proton/KWin has not been tested locally;
the fix still needs confirmation on the reporter's Linux machine.

## AMD divide by zero (#93)

The supplied RX 5700 XT dump faults at `Cyberpunk2077.exe+0x1F9A86`, inside
`ceil(width / tileSize)`, called from `+0x76FCAC` (return `+0x76FD6B`). Width is
1832 and the tile divisor is zero. The allocator belongs to the engine's
PrepareShadingRateImage node and is gated by F1 bit 20 (overall feature 84).
It reads its tile size from `*(*[exe+0x3438A28]+0xB)` in game version 2.31.

The report's log has main F1 `0x0507F008`, while forced VRCAM F1 is
`0x0517F009`: the NVIDIA-seeded template enables an unsupported VRS image.
Microsoft's [VRS specification](https://microsoft.github.io/DirectX-Specs/d3d/VariableRateShading.html)
likewise defines zero shading-rate tile size for unsupported VRS.

Filter only this flag when the engine reports a zero tile size, at both the
flag-computation and builder-OR force points. Do not modify the native divider,
main-view flags, any other feature, or graphics settings. Nonzero native tile
sizes preserve all flags; the current NVIDIA session reported 16. The filter
logs once when it removes the unsupported feature.

Regression tests replay the recorded flag values and allocator condition,
cover every other bit, and ensure the later OR cannot reintroduce VRS.
There is no local RX 5700 XT, so this is a targeted fix for the supplied crash,
not a claim that all AMD compatibility has been validated. Native disassembly
evidence is saved under `build/issues-70-71-93-20260928/`.
