## Реализация

- Пакет содержит `pose_id`, отдельный `write_id` записи компонента, компонент,
  глаз, относительную HMD-позу с origin и её согласованную OpenXR local pose.
  Native `pose_id` соответствует номеру полного пакета головы/рук с bit63;
  XR-latched sample использует свой sequence, отдельные legacy samples — bit62.
- `PoseAddressLedger` переносит пакет по адресу объекта и поколению публикации.
  Fingerprint только проверяет неизменность известного объекта. Поиск по
  координатам не используется в этом пути. Если источник изменился во время
  копирования или не размечен, назначение теряет метку.
- MAIN перехватывается перед сериализацией: ID берётся до чтения компонентных
  полей. В4E9398 используется фактически выбранный аргумент CameraSetup,
  поэтому более раннее наблюдение director+4C0 не подменяет override-камеру.
- VRCAM получает собственную метку в области вызова AC2BA4 и переносит её
  через конструктор полного descriptor. Восемь новых hooks и общий копировщик
  проверены по сигнатурам из `CameraPoseSites.hpp`.
- `FinalCamera` предпочитает ID конкретного camera buffer. Старый поиск
  остаётся запасным путём при неизвестной связи и учитывается отдельно.
- В узлах рендера берётся метка context+70. Она записывается вместе с целевыми
  ресурсами в metadata списка команд. Reset отбрасывает незавершённую запись;
  публикация происходит после фактического ExecuteCommandLists.
- Уничтожение ресурсов/списков очищает metadata. Повторное использование
  адреса ресурса имеет отдельное поколение. Привязка к жизни COM-объекта
  реализована через [SetPrivateDataInterface](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12object-setprivatedatainterface);
  возвращаемая [GetPrivateData](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12object-getprivatedata)
  ссылка освобождается после чтения.
- В Present метки берутся от фактически выбранных ресурсов под общим
  порядком отправки команд. Для прямой привязки проверяются глаз, origin и
  совпадение очереди источника с очередью копирования. Статическая геометрия
  глаза переносится на head pose изображения; свежая HMD-поза не подставляется.
- Каждый слот VRCAM хранит собственные pose/FOV/ID. Найдена и устранена
  ошибка прежнего reuse: выбирались старые пиксели, но сохранялась поза MAIN
  текущего кадра. Теперь повторный показ берёт и старую позу того же слота.
- MAIN и VRCAM выбираются вместе под publication mutex. Read reservations
  не позволяют производителю перезаписать выбранные пиксели. Ссылки на старые
  ресурсы удерживаются до завершения GPU fence; ожидание нового кадра не добавлено.
- ID передаётся в CapturedMonoFrame и до успешного xrEndFrame. Добавлены
  отдельные счётчики прохождения и отказов для обоих источников, а также ID
  пакета, использованного VRIK, и признак смены входа во время solve.

## Проверки и предел результата

Успешно:13 тестов pose identity/ABI,27 roomscale/pose тестов,19 VRIK тестов.
Четыре build-only мутации обнаружены: устаревшее поколение адреса, публикация
во время копирования, сохранение сброшенного списка команд и перезапись
выбранного читателем изображения. Release DLL собрана после полной пересборки
и исправления ошибок сборки; окончательный лог `build/pose-id-final-build-12092.log`.
Стенды используют производственные протоколы и математику, но не выполняют
движок, GPU и OpenXR compositor. Новая DLL ещё не проверена живым запуском.

Пока не заявляется100% покрытие ID в runtime. Остались явные запасные пути
для неизвестного/изменившегося источника, смены origin и неподтверждённой
очереди записи. Следующий тест должен проверить `PoseIdFinalMiss` и
`PoseIdCaptureMiss` отдельно для MAIN/VRCAM в обычном gameplay, переходах и
повторном показе. Цель — подтвердить цепочку, а не назвать fallback точным ID.
