# Проверка pose_id, PID25496, 21.09.2026

Проверялась DLL `dd0f7300…` с первой реализацией сквозных ID для MAIN/VRCAM.
Встроенный x64dbg подключён к новому PID; база DLL0x7FFA0D790000,
EXE0x7FF672000000. В логе `CameraPoseTransport ok`.
Адреса сохранены в `build/vrik-live-25496-addresses.json` и относятся только
к этому уже остановленному запуску.

- максимальный шаг кисти после300мс покоя≈0,005972мм, прежний скачок171мм
 не повторился. Максимальная ошибка shadow aliases≈0,000586мм;
- исходная поза симулятора восстановлена.

Счётчики читаются асинхронно, поэтому разница315/316 не объявляется отдельным

На движении VRCAM почти всегда сохраняла ID. На длительном покое он исчезал:
baseline54/54 отказа VRCAM, последний interval after59/59. Основной вид
сохранял ID во всех этих интервалах.

## Причина, исправленная после прогона

На остановленном вызове `RenderBuild`, сразу после false из DescriptorMatches,
сняты аргументы и вся таблица `PoseAddressLedger`:

- pending camera=context+1E20 и входной descriptor имеют одинаковые position/quaternion;
- исходная метка pending camera отсутствует, receipt generation=0;
- всего в таблице380 объектов при лимите8192;
- для VRCAM осталась только текущая запись компонента. Сохранённый движком
 descriptor component+2A0+330 и render context уже не имеют ID.

Артефакты: `render-descriptor-miss.json`, `ledger-at-vrcam-miss.json`.
Отдельный `retained-before.json` был снят с работающего процесса после
неудавшегося debug_pause; это вспомогательный асинхронный снимок, не доказательство
одного остановленного вызова.

Ошибка протокола: прежнее кольцо ограничивало последние8192 **публикации**,
хотя реальные объекты гораздо реже меняют адрес. Тысячи обновлений MAIN
выбрасывали ID неизменного descriptor VRCAM. Движок продолжал переиспользовать
тот же descriptor, но перенести его ID уже было неоткуда.

В `PoseAddressLedger.hpp` предел теперь относится к числу **разных объектов**.
Обновление существующего адреса не вытесняет другой адрес. При реальном
переполнении вытесняется объект с самым давним использованием. Capture
обновляет порядок использования, сохраняя generation; явная инвалидизация,
смена поколения и проверка fingerprint остаются обязательными.

создаёт неизменную VRCAM, многократно обновляет MAIN, повторно копирует
VRCAM, затем создаёт новые адреса и проверяет сохранность активной камеры.

- 14/14 pose identity/ABI тестов прошли:
  `build/pose-id-25496-ctest.log`;
- отдельная сборка с **точной старой копией** заголовка из checkpoint падает
 на ожидаемом `unrelated MAIN publications expired a cached VRCAM pose`:
  `build/pose-id-cache-before-test/`;
- 5/5 build-only регрессий обнаружены:
  `build/pose-id-regression-probe/results.json`;
- Release DLL собрана: `build/pose-id-25496-build.log`;
- изменён только производственный протокол хранения ID. Код камеры,
 OpenXR prediction, roomscale, калибровка и VRIK solver не менялись.
