# Остаточный рывок тела/рук при HMD, PID20936

## Что подтвердил пользователь

После установки `ba77eaf9...` пользователь запустил игру (PID20936).
Ответ по плавности: **«Без заметных изменений»**. Уточнил, что дёргаются
**тело и руки**, и отдельно напомнил: **при WASD такого дёрганья нет**.
Эти наблюдения приняты; успешные проверки камеры не считаются устранением рывка.

## Где обнаружен большой скачок

`g_AnimPoseLastBoneBuf` указывает на буфер, который после локального pose apply
движок преобразует в MODEL space. Повторное накопление parent chain у уже
модельных позиций даёт ложные многометровые числа. Первая попытка
`*-bone-buffer.json` ошибочно читала все стадии как local; эти числа не являются
дефектом игры. Sampler теперь хранит `positions` напрямую и отдельно `if_local`.

В `*-bone-stage.json` отобраны стабильные чтения буфера в MODEL-стадии с
совпавшей опубликованной головой (ошибка менее0.001 мм). Наружу:

- голова: max step2.86 мм;
- таз: XY0, Z max step7.48 мм;
- правая кисть: **77.44 мм**, левая: **93.06 мм**.

На возврате кисти51.23/61.86 мм. В неподвижной фазе кисти меняются менее0.062 мм.
Чтения асинхронные; это не GPU-frame capture, но скачок есть уже в pose buffer.

`*-hand-packet-before.json` показывает ту же общую X-ошибку в данных ОБОИХ
контроллеров, до IK и калибровки. На возврате скачок входа61.35 мм превращается
в53.93/65.03 мм у кистей, согласуясь с reach scales `.879/1.060`.

Источник: `FlushHandsToShared` вызывался только из Present, независимо от CCT.
Его контроллеры заново запрашивались для `GetFrameAimTimeNow()`, а head reference
строился несколько раз из `m_pos*/m_ori*` XR-потока. Камера и CCT уже используют
другой общий latch `AcquireFrameHeadSample`. Пакет мог менять head basis между
локализацией, фильтром и публикацией `[124..126]`. При WASD неподвижная HMD-позиция
не создаёт эту разницу.

- PredictFilter3→0→3: реальная попытка сохранена в `*-hmd-filter0-verified.json`;
  не дала устойчивого общего улучшения по модельной траектории. Значение3
  восстановлено чтением памяти. Первый отказ записи running-target сохранён
  отдельно как `*-filter-toggle-rejected.json`, явно невалидный A/B.
- HandFilterInWorld1→0→1: `*-hand-filter-local.json`. Скачки стали меньше, но
  общий диапазон ошибки не исчез; значение1 восстановлено. Это не принято как fix.
- Также оставлены исходные HandRelToFilteredHead1 и HandLocatePerFrame1.
- `debug_pause` ненадёжен, иногда false; `script_execute pause` тоже может не
  остановить. Для ограниченных записей использован unconditional software BP
  на freshly resolved `OpenXRManager::Get`, удалён перед resume. Все BP удалены,
  hardware watch не применялся. INI/калибровка экспериментами не менялись.

## Новая правка (проверка в игре ещё предстоит)

- В latch HMD сохраняется точное XR-время запроса вместе с позой. При fallback
  на старый XR-cache время0, поэтому он не выдаётся за общий tracking frame.
- Native CCT callback при разрешённом on-foot roomscale публикует руки ДО
  physics/animation update из этой же позы HMD и этого же XR-времени. Повторное
  потребление одной frame sequence не делает вторую публикацию.
- Один захваченный head reference используется для локализации контроллеров,
  world-filter round trip, head quaternion, высоты и `[124..126]`. Повторных
  чтений изменяющегося `m_pos*` внутри публикации нет.
- Present не перезаписывает свежий native packet. `HandPublicationGate` возвращает
  прежний Present-путь при смене origin, истечении250 мс без CCT; eligibility
  для немедленного перехода в меню/машину проверяется под mutex публикации.
- Shared mapping и оба publisher защищены одним `m_handMutex`. Математика
  существующего фильтра рук, reach scales, параметры, Bake и формула CCT не
  меняются. При новом origin сбрасывается только история фильтра рук.
- Новые счётчики: `CyberpunkVR_NativeHandPublishes`,
  `CyberpunkVR_PresentHandPublishSkipped`, `CyberpunkVR_FrameHandReferenceRejected`.
  Лог `HandFrame: native=... presentSkipped=... rejected=...`.
