## Найдены ошибки

1. Совместное опускание HMD и двух привязанных к нему рук вызвало всплытие.
   Абсолютного движения рук недостаточно: оно должно также происходить
   относительно головы/верхней части тела. В AscendStroke добавлена вторая
   проверка и регрессия с этой самой траекторией.
2. Roomscale: перенос HMD на 16 см и обратно дал примерно 1.36 м смещения
   персонажа; максимальная скорость около 5.98 м/с. Компенсация в двух
   предполагаемых точках плавания не вызывалась. Статические адреса этих
   calls не доказывали, что активное состояние пользуется именно ими.
3. Жест брасса давал native detector forward=1 и automatic=true, но собственные
   действия PSM SwimmingDivingEvents оставались MoveY=0, Jump=0,
   ToggleSprint=0, IsMoveInputConsiderable=false. Это измерено ограниченным
   ObserveAfter на реальном OnUpdate. Причина не объявляется фокусом окна.

Сырые файлы: `build/swimming-water-22616/posture.json`, `roomscale.json`,
`forward.json`, `forward-observed.json`, `summary-before-native-action-fix.json`.
Брассовый setup в этом пробнике тоже может распознаться при возврате из
начальной позы; полное число распознаваний не равно числу именованных pulls.

## Следующее исправление

- Ввод жеста подаётся в общий native reader CName action-таблицы
  (`0x4C6C9C`), только для input object текущего игрока. Объект привязывается
  в существующем OnFootMoveXY через тот же context getter, который вызывает
  оригинальный sampler. Provider проверяется по текущему GetPlayer,
  владению movement component и vtable. Чужие/старые input objects исключены.
- Скриптовые решения Swimming читают ту же команду через кооперативные
  Override GetActionValue/IsActionJustPressed. Оригинальные функции вызываются,
  другие действия и акторы сохраняются. Путь проверен в настоящем CET
  проходным override: owner=player=1ULL, CName.value доступен, ошибок нет.
  Позиции HMD/рук через Lua не передаются.
- Дублирующий ввод жестов в XInput убран; обычный контроллер остаётся в XInput.
- Скорость воды фильтруется в общем reader physics property4 (`0x23F168`),
  размер 12 байт, только для совпадающего physics handle и свежего результата
  CCT. Данные backend не переписываются. Наземный solver сохраняет прежний
  отдельный путь. Повторное вычитание через provider исключено в воде.
- Нативные сигнатуры проверяются перед установкой. Оба provider-call адреса
  оставлены только как историческая диагностика; живые счётчики показали,
  что они не покрывали текущий водный путь.

12 синтетических тестов плавания прошли, включая ложное всплытие. Проверены
ABI property reader и Lua-модули. Mock CET проверяет 15 публикаций состояния,
подачу MoveY/Dive, сохранение других действий/акторов и native значений.

Новое движение и компенсация требуют повторной живой проверки после
установки. Исправную позу/5° нельзя считать подтверждением этих двух путей.
