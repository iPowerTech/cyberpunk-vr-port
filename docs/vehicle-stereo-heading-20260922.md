# Общая ориентация MAIN/VRCAM в автомобиле

Пользователь заметил разные направления глаз и чередование картинки в обычной
машине и passenger Combat. Состояние снято с PID28248 без снятия игровой паузы,
ввода в игру или записи её памяти. Работал Virtual Desktop OpenXR; файл статуса
симулятора относился к предыдущему запуску.

Артефакты: `build/vehicle-stereo-paused-28248/` — `snapshot.json`,
`summary.json`, `cause.json`, адреса символов установленной DLL и read-only
скрипт. Исходная DLL:
`7aa2f09ee07343277aa07e272e6a93a281e4ef07da023e33a01d2bdd97d16551`.

MAIN и VRCAM принадлежат одному текущему игроку. PSM vehicle=Combat (2),
scene tier=FullGameplay (1), menu mode=1. У обоих глаз совпали pose ID
capture/submit=9303; расхождение уже присутствовало в кватернионах компонентов.
В паузе обновления компонентов остановлены, поэтому разную активность
рендер-проходов на паузе не используем как свидетельство поведения в движении.

Причина в `PatchCamera.cpp`:

- общий кватернион был составлен с yaw=-157,155071°;
- нативный MAIN имел yaw=-125,189013°;
- `YawCatchUpOnSharedEpoch` отдельно доворачивал MAIN на +31,966059°;
- VRCAM оставался с общим кватернионом.

Расчёт `Rz(yaw(native MAIN)-shared yaw) * shared quaternion` совпал с реально
записанным MAIN с ошибкой 0,000002415°. Реальное угловое расхождение глаз —
31,966061°. VRCAM совпал с общей публикацией точно. Кроме этого, прежде общую
базу выбирал первый вызванный компонент, поэтому перестановка MAIN/VRCAM
могла менять её между кадрами.

Теперь нативный yaw поступает только от MAIN текущего игрока. Источник
привязан к идентичностям игрока и компонента и читается под тем же mutex, что
выбор общей композиции. MAIN наблюдается до записи VR-поворота, в том числе
пешком, чтобы источник был готов при посадке. Второй компонент не может
подменить базу. Пока MAIN ещё неизвестен, используется общая опубликованная
база LocateCamera. Почти вертикальная ориентация не создаёт фиктивный yaw.

Одна pose epoch сохраняет выбранный yaw для обоих глаз. Обновление нативного
MAIN между вызовами применяется на следующей epoch; это не отдельный доворот
второго глаза. Удалена поправка после `CamWriteQuatRead`. Её старые diagnostic
exports сохранены с нулевым значением для совместимости и больше не управляют
камерой. Общий путь действует при любом обычном mounted-состоянии, включая
Combat. Специальные базы braindance и device camera остаются в своих ветках.

Проверки:

- `vehicle_stereo_heading` воспроизводит прежние 31,9661° из снятых
  кватернионов; 64 синтетические позы с обоими порядками вызовов дают
  `corrected_pair_deg=0`, `callback_order_error_deg=0` и одну ось IPD;
- `vehicle_heading_identity` проверяет обновление MAIN между глазами,
  следующую epoch, общий bootstrap, смену игрока/компонента, вертикальный
  forward, NaN/Inf, нулевой кватернион и bootstrap epoch=0;
- пройдены `rendered_pose`, `native_camera_pair`, `render_roundoff`,
  `hand_view_sample`, `frame_aim`, `render_quantized_labels`.

Всего восемь целевых проверок. В тесте границ yaw учитывается эквивалентность
-π и +π. Это синтетическая проверка исправления; результат новой DLL в шлеме
ещё нужно проверить после установки.
