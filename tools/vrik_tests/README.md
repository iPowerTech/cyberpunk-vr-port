# Синтетический стенд цепочки VRIK

Стенд компилирует **производственные** `CharacterRig.cpp`, `HandSnapshot.cpp`
и общие функции `Utils/XrMath.hpp`, `Camera/AnchorTranslation.hpp`.
FK сверяется со снятым из игры буфером из 619 костей. Источники и SHA256
фикстур указаны в `fixtures/provenance.json`.

Внешние границы вынесены в `stubs.cpp`: поставщики пары камера/персонаж,
настройки, общая память. Обращение к настоящему OpenXR из этих заглушек
завершает тест аварийно; успешный запуск не подменяет проверку runtime/GPU.
Хук `AnimPose` целиком в тестовый EXE не входит; в игре он вызывает те же
функции построения цели, согласования поз, IK и повторной записи.

После конфигурации основного проекта, которая подготавливает зависимости:

```powershell
cmake -S tools/vrik_tests -B build/vrik-tests
cmake --build build/vrik-tests --config Release
ctest --test-dir build/vrik-tests -C Release --output-on-failure
```

Проверка чувствительности тестов:

```powershell
python tools/vrik_tests/regression_probe.py
```

Она возвращает шесть старых ошибок в копии исходников внутри
`build/vrik-regression-probe`, собирает отдельный EXE и требует, чтобы все
шесть проверок завершились соответствующей ошибкой. Рабочие исходники и
игровая DLL не меняются.

`paired_consumed` проверяет, что следующий физический шаг не меняет остаток
позиции HMD у предыдущего пакета рук, в том числе при незаконченной записи.
`pair_selection` проверяет обязательную native-пару пешком и сохранение
Lua-пары для транспорта и старого пути композиции камеры.

Для сборки от 20.09 22:58 в конфигурации `live_chain_probe.py` нужен
`native_owner_packets: true`: native-пакет содержит owner, origin и stamp.
Поля адресов `previous_entity_epoch` и `last_paired_camera_seq` больше не
обязательны. Все адреса после нового запуска разрешаются заново.

`pose_chain` проводит 362 пакета через преобразование контроллеров относительно
HMD, реальный читатель shared memory, пакет вида, пару камера/персонаж,
построение цели, настоящий решатель рук и синхронизацию теневых костей.
Меняются позиция и ориентация HMD, система отсчёта после recenter и метка
головы у исходного вида. Входные контроллеры неподвижны. Независимая ожидаемая
цель строится непосредственно из их позиции в tracking space.

Стенд проверяет преобразования и порядок публикаций. Он не моделирует
рендерер, отдельный теневой компонент, игровые animation jobs, HUD-композитор
или фактический выбор позы драйвером OpenXR. Частота кадров не является
объяснением или изменяемым параметром этого исследования.

`weapon_stance` и `weapon_stance_armed_start` используют отдельный набор
из620 костей, снятый без оружия и с дробовиком в PID7296 (21.09.2026).
Производственные постановка тела, arm frame, постановка ключиц, IK, shadow и
replay проходят одинаковые входные цели при чередовании четырёх native-поз.
Проверяются плечи, локти, кисти, SHL/deltoid/scapula/trapezius/wrist helpers
и их shadow aliases. Local ног/служебных костей и scale должны сохраняться.
`body_arm_frame` отличает корректный поворот с тазом от ошибочной зависимости
от головы или постоянной единичной системы координат. Происхождение нового
набора: `fixtures/weapon_stance/provenance.json`.

`pose_buffer_rebind` подаёт настоящему FK уменьшенный pose-буфер перед
PAGE_NOACCESS при устаревшем размере768. Проверка границы должна остановить
обращение; после завершения перепривязки обработка восстанавливается. Отдельный
поток проверяет блокировку обработки на время обновления метаданных скелета.
